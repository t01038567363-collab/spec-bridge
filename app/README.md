# Spec Bridge 앱 (MVP 시연용)

TRD v3(`TRD.md`) + 프로토타입(`spec_bridge.html`) + TRD v2.0 PDF를 하나로 합친 **클라이언트 전용 웹앱**입니다. 빌드·서버 없이 `index.html`을 브라우저로 열면 됩니다.

## 구성
- `index.html` / `js/app.js` — 4단계 UI(기업 → 업로드 → 사전검사 → 리포트), TXT·JSON·복사 내보내기
- `js/data.js` — 기준 데이터: 문서 12항목, 수치 체크리스트 Q01~Q10, 샘플 답변·문서
- `js/engine.js` — 결정적 규칙 엔진, 초안 생성기(템플릿 + 선택적 LLM 훅), 금지 표현 필터
- `tests.html` / `js/tests.js` — 단위 테스트 27건(브라우저에서 `tests.html` 열기)

## 두 가지 검사
1. **A. 문서 12항목**: 업로드 문서의 키워드 3개 이상 충족 / 1~2개 보완 / 0개 누락. 가중치 합(105)을 100점으로 정규화. 근거가 없으면 판정을 만들지 않고 누락 처리.
2. **B. 수치 10문항**: 값·단위·증빙을 규칙으로 대조해 충족 / 미흡 / 확인 필요 판정. AI는 판정에 관여하지 않고 초안 문장만 만듭니다.

## 정책 모드
- `demo`: 후보 기준값으로 시연 판정(“원문 대조 전” 표기). 기업 A 기본 입력 → 충족 6 · 미흡 2 · 확인 필요 2
- `strict`: `source_status: 'unverified'` 문항은 전부 확인 필요
- 원문 대조 후 `js/data.js`의 해당 문항 `source`에 실제 조항·쪽수를 넣고 `source_status`를 `'verified'`로 바꾸면 strict에서도 판정됩니다.

## 한계
- 규격 조항·쪽수와 Q01~Q03 값은 **미확정(가정)** 입니다. 공식 인증·심사가 아닙니다.
- FastAPI 백엔드·DB·실제 LLM 호출은 포함하지 않습니다(LLM은 `generateChecklistDraft(results, { llm })` 훅만 제공, 실패 시 템플릿 폴백).
- 데이터는 브라우저 메모리에만 있으며 저장·전송되지 않습니다. PDF 읽기는 PDF.js CDN을 사용합니다(오프라인이면 파일명만 사용).

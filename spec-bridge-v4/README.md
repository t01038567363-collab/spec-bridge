# 스펙 브릿지 (Spec Bridge) v5 — 서버형 · 최종 실행 대상

국방 규격서의 요구사항과 기업 제출 자료를 **문장 단위로 대조**해 충족 / 보완 필요 / 누락을 판정하는 사전 점검 도구입니다. 점수(가중치)는 쓰지 않고, 규격 원문 ↔ 기업 자료 근거 문장을 함께 보여 줍니다.

v5부터 **로그인 + 서버측 비교 엔진 + 검사 기록 DB**를 갖춘 Node.js 서버형입니다(외부 npm 패키지 없음).

> ⚠ 공식 적합 판정이 아닌 **사전 점검 보조 도구**입니다. 군사기밀·개인정보·영업비밀 자료는 올리지 마세요. PDF 텍스트 추출은 브라우저에서 하지만, 비교를 위해 **추출된 텍스트가 서버로 전송**됩니다. 업로드 원문은 저장하지 않고 결과(요구 문장·근거 문장)만 계정별 기록에 저장됩니다.
> 저장소의 `app/`은 이전 별도 구현이며, **최종 버전은 이 폴더(`spec-bridge-v4/`)** 입니다(폴더명은 호환을 위해 유지).

## 실행 방법
필요: **Node.js 18 이상** (https://nodejs.org). 설치할 패키지는 없습니다.

```
cd spec-bridge-v4
node server.js
```
→ 브라우저에서 http://127.0.0.1:3000 접속 → **가입** 후 로그인 → 1단계 기업/국방 선택 → 2단계 업로드(또는 `+ 샘플`) → 3단계 **검사 실행** → 4단계 리포트. 1단계 하단 "내 검사 기록"에서 과거 결과를 다시 열거나 삭제할 수 있습니다.

| 환경변수 | 기본값 | 설명 |
|---|---|---|
| `PORT` | 3000 | 포트 |
| `HOST` | 127.0.0.1 | 바인드 주소(외부 공개 시 `0.0.0.0` + 반드시 HTTPS 프록시) |
| `DATA_DIR` | `./data` | `db.json` 저장 위치(Git 제외됨) |
| `ALLOW_REGISTER` | true | `false`면 신규 가입 차단(계정 생성 후 운영 권장) |
| `SECURE_COOKIE` | false | HTTPS 뒤에서 `true` (쿠키 Secure 속성) |

Windows PowerShell 예: `$env:PORT=8080; node server.js`

## 구성 파일
| 파일 | 역할 |
|---|---|
| `server.js` | HTTP 서버: 정적 파일, 가입/로그인(scrypt), 세션, 검사 API, JSON 파일 DB |
| `engine.js` | 판정 엔진(순수 함수). 서버가 실제 판정에 사용, 브라우저에서는 단위 테스트에 사용 |
| `criteria.js` | 심사 항목 세트: 기업 21개 / 국방 47개 (`항목나누기.docx` 기준) |
| `index.html` / `app.js` / `styles.css` | UI(로그인, 4단계, 기록) — 판정은 서버 API 호출 |
| `vendor/` | pdf.js 3.11.174 (PDF 텍스트 추출, 오프라인) |
| `test.js` | 서버 통합 테스트(`node test.js`) |
| `tests.html` | 판정 엔진 단위 테스트(서버 실행 중 `/tests.html` 또는 파일로 열기) |

## API
`POST /api/register|login|logout`, `GET /api/me`, `POST /api/inspect`, `GET /api/inspections`, `GET|DELETE /api/inspections/:id`, `GET /api/health`. 쓰기 요청은 `X-Requested-With: spec-bridge` 헤더가 필요합니다(CSRF 방어).

## 판정 규칙
- **누락**: 규격 요구문과 연관된 기업 문장이 없음(연관도 < 기준값, 기본 0.40, 화면에서 조정).
- **보완 필요**: 연관 문장은 있으나 규격이 명시한 표준 번호가 없거나(규격이 개정기호 없이 `MIL-STD-810`이면 `810G`도 인정), 수치(이상/이하/±/동일)를 만족하지 않거나 수치가 없음.
- **충족**: 연관 문장이 있고 표준·수치가 모두 확인됨(서술형은 "정량 비교 없음" 표시).
- 항목 판정: 소속 요구가 모두 충족 → 충족, 모두 누락 → 누락, 그 외 보완 필요, 요구 없음 → 판정 제외.

## 보안 구현 범위
- 비밀번호: scrypt + 사용자별 salt, 상수시간 비교. 세션: 무작위 토큰(DB엔 SHA-256 해시만), HttpOnly·SameSite=Strict 쿠키, 8시간 만료.
- 로그인/가입 IP별 속도 제한, CSRF 헤더·Origin 검사, 요청 크기(30MB)·파일 수·입력 검증, 계정별 기록 격리, CSP·nosniff 등 보안 헤더, 정적 파일은 허용 목록만 제공.
- 업로드 텍스트에서 주민번호·전화·이메일·사업자번호·비밀/대외비 표시를 **패턴으로 탐지해 경고**합니다(차단 아님·불완전).
- **운영 전 필수 보완(범위 밖)**: HTTPS(TLS) 종단, 비밀번호 재설정·MFA, 감사 로그, 백업·DB 교체(현재 JSON 파일 — 소규모용), 서버 측 보안 심사·모의해킹. 군사기밀 취급 시스템에는 해당 보안 규정 승인이 필요합니다.

- Firefox·Safari는 직접 검증하지 않았습니다(표준 API만 사용).

## 한계
- 키워드·수치 기반 비교이며 의미 이해가 아닙니다. 연관도 기준값에 따라 결과가 달라집니다.
- 국방 추가 19개 영역은 실무 영역 정리이며 기품원 공식 조항 원문이 아닙니다. 공식 대조는 KDS STD-0005-1 및 최신 심사기준표가 필요합니다.
- 항목 세트·분류 키워드는 KS Q ISO 9001·KDS STD-0005-1 원문의 조항·쪽수와 **교차 확인되지 않았습니다**.
- 스캔 PDF·DOC·XLS·HWP는 텍스트를 추출하지 못하므로 변환 후 올려야 합니다.
- UI e2e 자동 테스트는 없습니다.
